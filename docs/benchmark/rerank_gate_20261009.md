# [실측 리포트] 한국어 Cross-Encoder 리랭커 점수 기반 품질 게이트 검증 (#428)

> **한 줄 요약 (BLUF):** 후보 리랭커 3종 모두 H1(음성 차단율 70% 이상, 양성 오차단율 10% 이하)을 충족하지 못했습니다. 최고 성적은 `nlpai-lab/KURE-Reranker-nano`의 **차단율 56.8% / 오차단율 9.9% (AUC 0.817)** 이며, LLM 평가기의 차단율 88.4%에 미치지 못합니다. 따라서 **H1, H2, H3를 모두 기각**하고, 리랭커 점수 게이트로 LLM 평가를 대체하거나 위임 구간을 두는 방식을 채택하지 않습니다. `RERANK_MODEL`과 `RERANK_THRESHOLD`의 현행값은 변경하지 않습니다.

## 1. 실험 환경 및 측정 조건

- **측정 일시:** 2026-10-09 00:30 ~ 05:42 KST
- **코퍼스:** 로컬 DB 전체 1,507청크 (`chapter` 메타데이터 포함)
- **모집단:** `data/test_data/benchmark.jsonl` 114건 중 #183 정답 확정 대기 3건을 제외한 111건
- **검색:** 운영과 같은 하이브리드 검색(`search_chunks`, Dense + Sparse RRF)
- **양성 케이스:** 전체 코퍼스 검색 상위 10개 청크입니다. 111건 중 109건은 상위 10개에 정답 장 청크가 실제로 포함됩니다.
- **음성 케이스:** 상위 50개를 검색한 뒤 정답 장(`references`의 "제N장") 청크를 제거한 상위 10개입니다. 같은 질의에 대해 같은 도메인의 유사 오답(hard negative)만 남기는 방식입니다. 13건은 제거 후 남은 청크가 10개 미만이며, 남은 청크로 채점했습니다.
- **판정 신호:** 질의별 10개 청크 리랭커 점수의 최고값입니다. 점수는 `src/retrieval/reranker.py`와 같이 sigmoid로 정규화했습니다.
- **추론 조건:** CPU(8 논리코어), 질의+청크 512토큰 상한
  - `근거:` 상한이 없으면 bge-m3 계열이 8,192토큰까지 처리하여 첫 모델 하나가 75분 이상 끝나지 않았습니다.

- **원시 데이터:** `docs/measurements/issue428/` (`.gitignore` 대상이므로 로컬에만 보관합니다)
  - `gate_dump_20261009_0030.json`: 양성/음성 청크 덤프
  - `gate_scores_20261009_0215.json`: KURE-Reranker-nano

## 2. 모델별 결과

| 모델 | AUC | 최적 임계값 | 음성 차단율 | 양성 오차단율 | 임계값 0.5 차단율 / 오차단율 | 양성 중앙값 | 음성 중앙값 | 지연 p50 (10쌍) |
|---|---|---|---|---|---|---|---|---|
| `BAAI/bge-reranker-v2-m3` (현행 기준선) | **0.824** | 0.705 | 45.9% | 8.1% | 37.8% / 4.5% | 0.980 | 0.784 | 15.8초 |
| `dragonkue/bge-reranker-v2-m3-ko` | 0.758 | 0.0002 | 38.7% | 9.9% | 73.9% / 34.2% | 0.989 | 0.025 | 15.8초 |
| `nlpai-lab/KURE-Reranker-nano` | 0.817 | 0.945 | **56.8%** | 9.9% | 13.5% / 0.9% | 0.998 | 0.922 | **6.7초** |
| `nlpai-lab/KURE-Reranker-base` | 측정 불가 | | | | | | | 10건 미만 처리/90분 |
| (참고) LLM 평가기, #425 | | | 88.4% (76/86) | | | | | 약 2.5초 |

- 최적 임계값은 양성 오차단율 10% 이하 조건에서 음성 차단율이 최대인 값입니다.
- `KURE-Reranker-base`는 Qwen3 기반 약 17억 파라미터(28층, 3.3GB) 모델입니다. CPU에서 90분 동안 10건도 처리하지 못하여 측정을 중단했습니다.
- `dragonkue` 모델은 음성 점수를 강하게 낮추지만(중앙값 0.025) 양성 일부도 함께 낮춥니다. 그 결과 오차단율 10% 조건에서는 임계값이 0.0002까지 내려가고 차단율이 떨어집니다.

### 확신 구간(3구간) 분석

| 모델 | 즉시 차단 (< low) | LLM 위임 | 즉시 통과 (≥ high) |
|---|---|---|---|
| `BAAI/bge-reranker-v2-m3` | 2.3% | 86.0% | 11.7% |
| `dragonkue/bge-reranker-v2-m3-ko` | 0.5% | 95.0% | 4.5% |
| `nlpai-lab/KURE-Reranker-nano` | 3.2% | 93.2% | 3.6% |

- low는 양성을 하나도 차단하지 않는 최대 임계값이고, high는 음성을 하나도 통과시키지 않는 최소 임계값입니다.
- 모든 모델에서 86% 이상이 위임 구간에 속합니다. 따라서 2단계 위임 방식으로도 LLM 평가 호출을 15% 이상 줄일 수 없습니다.

## 3. 가설 판정

| 가설 | 판정 | 근거 수치 |
|---|---|---|
| **H1 (판별력)** | **기각** | 최고 차단율은 56.8%(nano)로 기준 70%에 미달합니다. 같은 오차단율 조건에서 기준선은 45.9%입니다. |
| **H2 (비용·지연)** | **기각** | CPU에서 질의당 10쌍 채점 지연이 6.7~15.8초로, 상한인 LLM 평가 1회(약 2.5초)를 크게 넘습니다. 위임 구간이 86% 이상이므로 LLM 호출 절감 효과도 15% 미만입니다. |
| **H3 (도메인 적합성)** | **기각** | 한국어 파인튜닝 `dragonkue` 모델의 AUC(0.758)는 다국어 기준선(0.824)보다 낮습니다. `KURE-Reranker-nano`(0.817)도 기준선과 사실상 같습니다. |

- `근거:` H1이 기각되었으므로 #428 계획에 따라 `benchmark` 마커 파이프라인 실측(LLM 비용 발생)은 수행하지 않았습니다.

## 4. 해석 및 한계

- 리랭커는 "같은 장 안에서 무엇이 더 관련 있는가"라는 순위 신호에는 유용합니다. 그러나 "근거가 전혀 없는가"라는 절대 판정 신호로는 약합니다. 같은 도메인의 다른 장 청크도 질의 용어를 공유하므로 최고 점수가 높게 유지됩니다(음성 중앙값 0.78~0.92, dragonkue 제외).
- 음성 구성 방식에는 한계가 있습니다. 정답 장 이외의 장에도 질의에 부분적으로 답할 수 있는 내용이 있을 수 있습니다. 이 경우 일부 음성은 실제로는 근거가 있는 케이스이므로 차단율이 과소추정될 수 있습니다. 그러나 이 효과를 감안하더라도 70% 기준과의 격차(13%p 이상)를 메우기는 어렵다고 판단합니다.
- 지연은 GPU 환경에서 크게 줄어들 수 있습니다. 다만 H1이 기각되었으므로 GPU 재측정의 실익은 낮습니다.

## 5. 운영 코드에 대한 관찰 사항

- `src/retrieval/reranker.py`는 `CrossEncoder`에 `max_length`를 지정하지 않습니다. 따라서 `USE_RERANKER=true`를 켜면 CPU 환경에서 질의당 수십 초 이상의 지연이 발생할 수 있습니다. 리랭커를 다시 활성화할 때는 길이 상한을 함께 적용해야 합니다.
- Windows 호스트에서 `POSTGRES_HOST=localhost`로는 psycopg 커넥션 풀이 연결을 얻지 못하고 시간 초과가 발생했습니다. `127.0.0.1`로 지정하면 정상적으로 동작합니다. 이번 실측은 셸 환경변수로 우회했습니다.

## 6. 결론 및 #405 반영 사항

- 리랭커 점수는 #405 옵션 B(2-Tier)의 Tier 분기 확신도 신호원으로 부적합합니다.
- CRAG 품질 게이트는 현행 LLM 평가기를 유지합니다.
- `RERANK_MODEL`, `RERANK_THRESHOLD`, `USE_RERANKER`의 현행값은 변경하지 않습니다.
