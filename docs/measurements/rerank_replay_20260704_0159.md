> **한 줄 요약(BLUF):** 한국어 리랭커 `bge-reranker-v2-m3`는 사전 확정 기준 4항목을 **전부 미충족**(Hit@1 4→2 · 회귀 3건 · MRR −0.150 · p50 3.96s)이라 **롤백**한다 — `USE_RERANKER=false` 유지, 라이브 A/B는 수행하지 않는다. 부수 확정 2건: ① RRF-k {30/60/90/120} 결과가 완전 동일 → 벤치마크에서 sparse 기여 0(plainto_tsquery AND 의미론)이라 **k 튜닝 레버 부재**. ② 현행 기본 모델 ms-marco는 Hit@1 0/14 · 절단률 77%로 한국어에서 무용(기본 off라 무해).

## 측정 조건

- 코퍼스: 1072청크 · 33장(덤프 시점 스탬프) · 벤치마크 14질의(K-GAAP)
- 방법: search-only 덤프(dense/sparse 사이드별 top-10, 질의당 검색 1회) → 오프라인 재정렬·채점(`scripts/rerank_replay.py`) — LLM·CRAG 개입 0, 결정적
- self-check: 오프라인 병합(k=60) == 라이브 `search_chunks()` 순서 **14/14 일치**
- canonical 대조: 리플레이 baseline 검색 Hit@1 4/14 = baseline_2057과 일치(원질의 채점이라 MRR은 rewrite 효과만큼 차이)
- 채점: `benchmark_metrics.rank_hit(exact)` / `retrieval_pass`(top-5 core) 재사용, 시그모이드 정규화(운영 reranker와 동일)
- 지연: 웜 상태에서 케이스별 10쌍 배치 추론(호스트 MPS `mps:0`), 콜드스타트는 최초 다운로드 포함

## 점수 분포 — 임계값 캘리브레이션 불가 근거

bge의 gold(9쌍) / 비gold(131쌍) 시그모이드 점수가 같은 구간(0.5~0.8)에 중첩된다:

- gold: 0.5–0.6 ×3 · 0.6–0.7 ×4 · 0.7–0.8 ×2
- 비gold: 0.5–0.6 ×83 · 0.6–0.7 ×32 · 0.7–0.8 ×16

분리 경계가 없어 `RERANK_THRESHOLD` 캘리브레이션으로 구제할 수 없다 — 게이트를 어디에 둬도 gold와 비gold가 함께 잘린다.

## 시사점 · 후속

1. **`USE_RERANKER=false` 유지** — 채택 후보 없음. 라이브 A/B는 리플레이 단계 탈락으로 수행하지 않는다(확정 구성 부재).
2. **RRF-k 튜닝 레버 부재 실측 확정** — 전체 자연어 질의는 sparse 0건(AND 의미론, 메타데이터 필터와 무관 — 단일 키워드는 5건 반환). 단일 리스트 RRF는 k와 무관하게 동일 순서다.
3. 검색 정확도 개선 여지는 리랭킹·k가 아니라 **sparse 활성화(질의 토큰 OR화 등)·rewrite·청크 입도** 쪽에 있다 — 본 트랙 비범위.
4. 재현: `uv run python scripts/rerank_replay.py dump` → `replay --dump-file <dump.json>`. raw JSON(dump·result)은 gitignore 대상이며 본 리포트가 기록 정본이다.
