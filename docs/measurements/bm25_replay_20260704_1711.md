# BM25 오프라인 실측 (Phase 0) — 전 arm #159 미달, 병목은 IDF가 아니라 토큰화 (2026-07-04)

> **한 줄 요약(BLUF):** IDF(inverse document frequency: 흔한 단어일수록 가중치를 자동으로 낮추는 값)를 내장한 진짜 BM25를 오프라인으로 재현해 (토크나이저 × IDF) 조합 3종을 쟀으나, **다섯 arm 모두 #159 채택 게이트(Hit@1 순증 ≥2·회귀 0·MRR Δ>0) 미달**이다. 두 축을 갈라 보니 결론이 뒤집혔다 — **IDF 단독은 무력하거나 오히려 해로웠고**(whitespace 토큰화에서 IDF를 더한 `bm25_ws`는 IDF 없는 `ts_or`보다 Hit@1 3→2·MRR 0.288→0.244로 악화), **개선은 전적으로 토큰화 축에서 나왔다**(`bm25_morph`의 retrieval_pass 9/14는 baseline plainto의 7/14를 넘고, 003·004·013에서 검색 상위 진입). 이는 #211 2차의 결론("병목 = ts_rank_cd의 IDF 부재")을 정정한다: **진짜 병목은 IDF 부재가 아니라 매칭 실패(토큰화)**였다 — "외화환산손익"이 한 덩어리로 남으면 IDF가 감쇠할 매칭 자체가 없기 때문이다. 다만 토큰화를 형태소로 근사한 `bm25_morph`조차 Hit@1은 순증 1 < 회귀 2로 게이트를 못 넘었고, 실제 형태소 사전(ko-dic) 랭커로 가도 Hit@1 극적 개선을 기대할 근거가 약하다. **sparse 트랙을 재보류하고 이 발견을 기록해 #226을 종료한다.**

## 측정 조건

- 코퍼스: **1507청크** · 33장 (#101 재적재 후 신 코퍼스, 1·2차와 동일)
- 벤치마크: 14질의(K-GAAP, standard=GAAP 단일)
- 방법: 질의별 dense 1회 + arm별 sparse → 운영과 동일한 RRF(k=60)로 병합해 채점 (`scripts/bm25_replay.py`)
- BM25 arm: 전 코퍼스를 오프라인 `BM25Okapi`(`rank_bm25`)로 인덱싱(토크나이저당 1벌). dense와 **동일한 metadata 필터(GAAP)**·"매칭 문서만"(0점 제외) 규약을 지켜 RRF 병합을 공정하게 맞춤. 인덱스는 케이스마다 재구축하지 않고 1회만 만듦(형태소 인덱스 구축은 질의당 비용이 아니라 1회 비용).
- DB arm: 1·2차 하니스의 `sparse_search_predicate`(운영 `searcher.sparse_search`와 동일한 `_execute_search_query`·타임아웃·예외 정책) 재사용.
- self-check: 현행 동작(plainto arm)의 오프라인 병합 == 라이브 `search_chunks()` 순서 **14/14 일치**.
- 채점: `benchmark_metrics.rank_hit(exact)` / `retrieval_pass`(top-5 core) 재사용 (1·2차·rerank_replay와 동일).
- dev 의존성: `rank-bm25` 0.2.2 · `kiwipiepy` 0.23.2 (하니스 전용, 운영 dependencies 무변경).
- 산출물: `bm25_replay_20260704_1711.json` (git 추적 제외, 케이스별 검색 결과·토큰 포함).
- 판정 모집단: gold(정답 라벨) 확정 대기 3건(003·005·012, #183)을 뺀 **11건**.

## arm 정의 — 토큰화 × IDF 두 축을 가르기 위한 구성

| arm | 토큰화 | IDF | 경로 | 역할 |
|---|---|---|---|---|
| plainto (현행·기준) | simple(공백/구두점 분리) | 없음(ts_rank_cd) | DB, plainto_tsquery(AND) | baseline. 문장형 질의라 전 케이스 sparse 0건 → 사실상 dense 단독 |
| ts_or | whitespace(`\w+`) | 없음(ts_rank_cd) | DB, websearch_to_tsquery(OR) | IDF 대조군 (토큰화 고정, IDF만 없음) |
| bm25_ws | whitespace(`\w+`) | BM25 | 오프라인 | ts_or와 짝 → **IDF 순효과** |
| bm25_ngram | 문자 3-gram | BM25 | 오프라인 | bm25_ws와 짝 → **토큰화 순효과** |
| bm25_morph | 형태소(kiwipiepy) | BM25 | 오프라인 | bm25_ws와 짝 → **토큰화 순효과** |

`ts_or`↔`bm25_ws`는 토큰화를 whitespace로 고정하고 IDF만 켜고 끈 대조라 **IDF의 순효과**를, `bm25_ws`↔`bm25_ngram`/`bm25_morph`는 IDF를 켠 채 토큰화만 바꾼 대조라 **토큰화의 순효과**를 각각 분리해 잰다.

## 두 축이 드러낸 것

### IDF 순효과 — 음성 (`ts_or` → `bm25_ws`)

토큰화를 whitespace로 고정하고 IDF만 켰더니 Hit@1 3→2, MRR 0.288→0.244로 **악화**했다. IDF가 도움이 되려면 "정답 조항이 매칭은 됐는데 흔한 용어에 순위가 밀리는" 상황이어야 하는데, whitespace 토큰은 "외화환산손익"·"퇴직급여충당부채"처럼 조사·복합어가 통짜로 남아 정답 조항의 표현("외화환산"·"퇴직급여")과 **매칭 자체가 안 된다**(#81 부분일치 한계). 감쇠할 매칭이 없으니 IDF는 질의의 흔한 whitespace 토큰만 재가중해 노이즈를 키웠다.

### 토큰화 순효과 — 양성 (`bm25_ws` → `bm25_ngram`/`bm25_morph`)

IDF를 켠 채 토큰화만 바꿨더니 Hit@1 2→4(ngram)/3(morph), MRR 0.244→0.38로 뚜렷이 올랐다. 특히 `bm25_morph`의 retrieval_pass 9/14는 baseline plainto(7)를 넘는다. 형태소가 "외화환산손익"을 `외화/환산/손익`으로 쪼개 정답 조항 표현과 매칭시킨 결과다 — 004(7위→1위), 003(9위→3위), 013(미검출→4위)이 그 사례다.

### 그래서 #211 결론을 정정한다

#211 2차 리포트는 병목을 "ts_rank_cd의 IDF 부재"로 지목했으나, 이번 실측은 **IDF 단독(bm25_ws)이 오히려 악화**함을 보였다. 병목의 1차 원인은 IDF 부재가 아니라 **매칭 실패(토큰화)**이고, IDF는 토큰화가 매칭을 만들어 준 뒤에야 의미가 있다. 레버의 우선순위는 **토큰화 > IDF**다.

## 011 리트머스 — BM25로도 미구제

011(질의 "순액으로만 표시")은 plainto를 포함해 **전 arm None**이다. 정답 조항은 "상계"라는 용어를 쓰는데 질의에는 없다. BM25는 질의에 실제로 등장한 토큰으로만 문서를 찾으므로, 질의에 없는 표준 용어를 스스로 만들어낼 수 없다 — 이 어휘 간극은 rewrite(질의 재작성)의 몫이고, #211 1·2차에서 query 쪽 레버로 소진됐다(비범위).

## 결론 — sparse 트랙 재보류, 발견 기록 후 #226 종료

- **전 arm #159 게이트 미달** → Phase 1(ParadeDB pg_search 등 실제 랭커 인프라 도입) 진행 조건 불충족.
- 토큰화를 오프라인 형태소로 이미 근사했는데도 `bm25_morph`가 Hit@1 순증 1 < 회귀 2에 그쳤다. 실제 ko-dic 랭커로 인프라를 들여도(ParadeDB는 AGPL, VectorChord와 함께 ko-dic 미문서화) Hit@1 극적 개선을 기대할 근거가 약하다 → **sparse 트랙 재보류**.
- 다만 다음 발견을 남겨, sparse 트랙을 미래에 재개할 때의 출발점으로 삼는다:
  1. **레버 우선순위는 토큰화 > IDF.** IDF 단독은 무력하거나 해롭다.
  2. **#211의 "병목=IDF 부재" 결론을 정정.** 진짜 병목은 매칭 실패(토큰화)다.
  3. **`bm25_morph`는 검색 상위(retrieval_pass 9/14 > baseline 7)를 개선**했다. Hit@1(NFR-002 1순위)로는 못 이어졌으나, 재개 시 "IDF보다 형태소 토큰화부터"가 실측에 근거한 방향이다.
- 하니스(`scripts/bm25_replay.py`)와 순수부 테스트는 재현 자산으로 머지한다 — 재개 시 arm만 실제 랭커로 갈아끼우면 된다.
