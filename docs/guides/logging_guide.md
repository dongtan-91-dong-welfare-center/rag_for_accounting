# 로깅 가이드

본 문서는 프로젝트 전반의 로그 명명 및 작성 규칙을 정의합니다. 태그와 키 대응표의 정본은 `src/utils/config.py`의 `LOG_TAGS`와 `LOG_FIELD_KEYS`입니다.

## 1. 기본 원칙

- `src/` 하위에서는 `logger.info(...)` 같은 직접 호출을 사용하지 않고 `src/utils/logger.py`의 `log_kv` 헬퍼만 사용합니다.
  - `근거:` 본문 문자열과 JSON 모드용 `extra` 필드를 한 번에 생성하여 호출부의 이중 기재와 표기 불일치를 막기 위함입니다.
- 헬퍼를 거치지 않은 직접 호출은 `tests/unit/test_logging_standard.py`가 AST로 검출하여 실패 처리합니다.

```python
log_kv(logger, logging.INFO, "search", "하이브리드 검색 완료", 건수=len(results), 소요=elapsed)
# 텍스트: [search] 하이브리드 검색 완료 | 건수=7 | 소요=0.1234s
# JSON:   {"message": "...", "tag": "search", "count": 7, "elapsed_sec": 0.1234, ...}
```

## 2. 태그 규격

- 형식은 소문자 snake_case `[모듈명]`이며 모듈 식별자 용도로만 사용합니다.
- 허용 태그는 `config.LOG_TAGS`에 정의되어 있으며, 목록에 없는 태그는 `log_kv`가 `ValueError`로 거부합니다.
- 예외 클래스명과 함수명은 태그가 아니라 `오류=ValueError`, `함수=search` 형태의 키-값으로 기록합니다.

## 3. 메시지 본문과 구조화 필드

- 본문 형식은 `[태그] 설명 | 키=값 | 키=값`이며 설명과 키는 한국어로 통일합니다.
- 한국어 키는 `config.LOG_FIELD_KEYS`에 정의된 영어 snake_case 키로 `extra`에 함께 전달되어 JSON 모드(`LOG_FORMAT=json`)에서 필드 단위로 검색할 수 있습니다. 등록되지 않은 키는 `ValueError`로 거부합니다. 새 키가 필요하면 `LOG_FIELD_KEYS`에 먼저 추가합니다.
- 시간 단위는 `s`로 고정하고 소수점 4자리를 사용합니다. (예: `소요=0.1234s`)
- 예외 상세는 `오류=<예외 클래스명>`과 `상세=<메시지>`로 기록하고, 스택 트레이스가 필요하면 `exc_info=True`를 전달합니다.

## 4. 로그 레벨 기준

| 레벨 | 발생 조건 | 필수 메타데이터 |
|---|---|---|
| DEBUG | 중간 산출물과 내부 상태 (검색 후보 목록, 재작성 질의 원문) | 질의 식별 가능 값 |
| INFO | 단계 시작과 종료 같은 정상 흐름 | `소요`, 주요 건수 |
| WARNING | 폴백, 재시도, 임계값 초과처럼 결과는 생성되지만 품질이 저하될 수 있는 상황 | 원인, 대체 동작 |
| ERROR | 현재 요청이 실패했으나 서비스는 지속되는 경우 | `오류`, `함수`, `소요` |
| CRITICAL | 서비스 기동 불가나 복구 불가 상태 | `오류`, `함수` |

## 5. 질의 원문 노출 제한

- 질의 원문은 DEBUG 레벨에서만 기록하고, INFO 이상에서는 `질의길이=` 같은 비식별 값만 기록합니다.
  - `근거:` 운영 기본 레벨이 INFO이고 회계감사 질의에 거래처명과 금액 같은 고객 정보가 포함될 수 있어, 원문을 INFO 이상에 두면 운영 로그에 상시 저장됩니다.
