# Codex 플러그인 등록 가이드

본 문서는 Codex 환경에서 회계 기준서 RAG 플러그인을 로컬 마켓플레이스에 등록하고, 매니페스트 인식과 MCP 도구 연동 상태를 사람이 직접 검증하는 절차를 설명합니다.

## 1. 사전 요구

- `codex` CLI 설치 및 `codex login` 완료
- DB 및 임베딩 컨테이너 기동: `docker compose up -d database embedding`
- 모든 명령은 저장소 루트 디렉터리에서 실행합니다.

## 2. 왜 자동화(pytest)로 검증하지 않는가

프로젝트의 기존 단위 테스트 스위트는 외부 네트워크나 무거운 서브시스템 의존 없이 결정적으로 동작하는 것을 원칙으로 합니다. 그러나 플러그인 등록 검증은 `codex` 바이너리 실행, OpenAI 인증, 그리고 LLM의 확률적 판단 과정을 포함합니다. 이러한 요소를 pytest에 포함하면 테스트 안정성이 저하되므로, 개발자가 직접 확인하는 수동 체크리스트로 관리합니다.

## 3. 매니페스트 인식 확인

**판단 근거:** 매니페스트 파일(`src/.codex-plugin/plugin.json`)의 `skills` 필드가 유효하지 않은 경로를 가리키더라도 Codex CLI는 별도의 오류 메시지 없이 해당 스킬을 건너뜁니다. 따라서 플러그인 추가 명령이 성공하더라도 `plugin list`를 통해 활성화 상태를 직접 확인해야 합니다.

```bash
codex plugin marketplace add .
codex plugin add k-accounting@k-accounting-marketplace
codex plugin list
```

**판정 기준**: 마지막 명령 출력에 아래처럼 `installed, enabled` 상태가 보이면 통과다.

```
k-accounting@k-accounting-marketplace  installed, enabled  0.1.0  <저장소 경로>/src
```

이미 설치된 상태에서 반복 확인하려면 `codex plugin remove k-accounting@k-accounting-marketplace`로 지운 뒤 위 3줄을 다시 실행한다.

## 4. 스킬 트리거율 확인 (벤치마크 질의 14개 × 2회)

**근거:** 스킬 트리거는 키워드 매칭이 아니라 Codex가 질의를 `SKILL.md`의 `description`과 대조해 판단하는 확률적 과정이다(공식 문서: "Codex can choose a skill when your task matches the skill description"). 같은 질의를 두 번 넣어도 다른 결과가 나올 수 있으므로, 1회 시행만으로 "트리거된다"고 결론 내리면 우연한 결과를 일반화하는 오류에 빠진다.

`data/test_data/benchmark.jsonl`의 아래 14개 질의를 각각 **2회씩, 새 Codex 세션에서** 입력한다. 세션 화면에 `k-accounting` 스킬 적용 표시가 뜨거나 답변에 조항 인용이 붙으면 트리거된 것으로 판별한다.

| id | 질의 |
|---|---|
| TEST-K-GAAP-001 | K-GAAP에서 현금흐름표의 영업활동현금흐름을 간접법으로 구할 때, 대손상각비나 대손충당금 환입액은 어떻게 가감하나요? |
| TEST-K-GAAP-002 | K-GAAP에서 차입원가를 자본화할 때, 특정차입금과 일반차입금 각각에 대해 자본화가 강제사항인지 선택사항인지 규정이 어떻게 되나요? |
| TEST-K-GAAP-003 | K-GAAP 적용 기업인데, 기말 퇴직금추계액을 산정해 보니 전년도보다 금액이 감소했습니다. 이 감소분을 퇴직급여 환입(수익)으로 회계처리해도 기준서상 문제가 없을까요? |
| TEST-K-GAAP-004 | 회사가 전환사채(CB)를 발행했는데, K-GAAP 상에서 이를 사채(장기성부채)와 전환권대가(자본)로 분리해서 인식하는 것이 맞는지 확인 부탁드립니다. |
| TEST-K-GAAP-005 | 당사가 전환사채(CB)를 발행한 게 아니라 '투자(취득)'한 경우입니다. K-GAAP에서는 내재된 전환권을 주계약인 채권과 분리하여 별도의 파생금융상품(자산)으로 분류 및 표시해야 하나요? |
| TEST-K-GAAP-006 | 중소기업 임의감사를 나갔는데, 회사가 유형자산 감가상각비를 세법상 산식(정률법 등)으로 그대로 계산해 두었습니다. 이거 K-GAAP 상으로 허용되나요? |
| TEST-K-GAAP-007 | K-GAAP 기업이 채권형 매도가능증권을 보유하고 있습니다. 유효이자율법으로 상각을 먼저 한 다음, 기말 상각후원가와 공정가치의 차액을 매도가능증권평가손익(자본)으로 잡는 절차가 맞나요? |
| TEST-K-GAAP-008 | 과거 20년 말에 토지 재평가를 수행한 K-GAAP 기업입니다. 매 3년이나 5년마다 재평가를 수행한다는 문구가 있던데, 5년이 지나면 무조건 의무적으로 재평가를 다시 해야 한다는 뜻인가요? |
| TEST-K-GAAP-009 | K-GAAP 하에서 재평가모형을 적용 중인 토지/건물 등 유형자산을 처분할 때, 기존에 자본으로 인식해 둔 재평가잉여금은 당기손익으로 재분류조정(Recycling) 하는 것이 맞습니까? |
| TEST-K-GAAP-010 | K-GAAP에서 매도가능증권 중 지분상품을 처분할 때의 구체적인 회계처리가 궁금합니다. 기존에 인식했던 평가손익은 어떻게 처리하나요? |
| TEST-K-GAAP-011 | 회사가 기말에 외화환산손익을 계산한 후, 외화환산이익에서 손실을 뺀 순액으로만 손익계산서에 표시해 두었습니다. K-GAAP 상 외화환산손익을 이렇게 상계하여 순액 표시하는 것이 규정상 허용되나요? |
| TEST-K-GAAP-012 | 확정급여형(DB) 퇴직연금 제도를 운용 중인 K-GAAP 기업입니다. 별도의 계리평가보고서 없이, 사외적립자산 내역만 기록하고 퇴직급여충당부채는 기말 일시퇴직기준 추계액으로 설정하면 올바른 회계처리인가요? |
| TEST-K-GAAP-013 | K-GAAP 기업이 만기보유증권이나 장기성 채권을 보유하고 있을 때, 유효이자율법을 적용하여 이자수익을 인식해야 합니까? |
| TEST-K-GAAP-014 | 회사가 퇴직연금운용자산을 재무상태표에 계상할 때, 일부는 장기금융상품으로 잡고 일부는 퇴직급여충당부채의 차감 항목으로 쪼개서 표시했습니다. 분류 기준이 무엇인가요? |

**판정 기준**: 14개 질의 × 2회 시행 = 28회 전부 트리거되면 통과다. 트리거되지 않은 케이스가 있으면 해당 `id`와 실패 횟수를 아래 6번 기록표에 남기고, `SKILL.md`의 `description`에 그 질의에 나온 용어를 보강한다(공식 가이드: "주요 사용 사례와 트리거 단어를 앞에 배치"). 보강할 때는 `src/skills/`와 `.claude/skills/`을 함께 수정하고 `uv run pytest tests/unit/test_claude_skill.py`로 동기화를 확인한다.

## 5. MCP 도구 실제 호출 확인

**근거:** `codex mcp list`는 전역에 수동 등록한 서버만 보여주고, 플러그인에 번들된 MCP 서버는 이 목록에 나타나지 않는 것으로 확인됐다(3번 항목 검증 중 실측). 목록에 없다고 실패로 단정할 수 없으므로, 실제 세션에서 도구를 호출해 확인해야 한다.

Codex 세션에서 `k-accounting` 스킬이 적용된 상태로 §4 표의 `TEST-K-GAAP-001` 질의(현금흐름표 간접법)를 던진 뒤, 답변에 조항 인용이 포함되는지 확인한다. 질의를 이 케이스로 고정하는 이유: 임의 질의는 배선이 정상이어도 근거 부족 판정이나 HIL 중단으로 끝나 인용이 없을 수 있고, 그러면 정상 설치를 MCP 연결 실패로 오판하게 된다. 001은 검색이 안정적으로 근거를 찾는 케이스다.

**판정 기준**: 답변에 조항 인용이 하나 이상 포함되면 통과다. "MCP 도구를 찾을 수 없다"류의 에러가 나오면 실패이며, 이때는 ① Codex 세션을 저장소 루트가 아닌 곳에서 열지 않았는지 확인한다. ② `src/.mcp.json`이 가리키는 실행 커맨드(`uv run python -m src.mcp_server.server`)를 저장소 루트에서 직접 실행해 서버 자체가 정상 기동하는지 확인한다.
