# Codex 플러그인 등록 가이드

본 문서는 Codex 환경에서 회계 기준서 RAG 플러그인을 로컬 마켓플레이스에 등록하고, 매니페스트 인식과 MCP 도구 연동 상태를 사람이 직접 검증하는 절차를 설명합니다.

## 1. 사전 요구

- `codex` CLI 설치 및 `codex login` 완료
- DB 및 임베딩 컨테이너 기동: `docker compose up -d database embedding`
- 모든 명령은 저장소 루트 디렉터리에서 실행합니다.

## 2. 왜 자동화(pytest)로 검증하지 않는가

프로젝트의 기존 단위 테스트 스위트는 외부 네트워크나 무거운 서브시스템 의존 없이 결정적으로 동작하는 것을 원칙으로 합니다. 그러나 플러그인 등록 검증은 `codex` 바이너리 실행, OpenAI 인증, 그리고 LLM의 확률적 판단 과정을 포함합니다. 이러한 요소를 pytest에 포함하면 테스트 안정성이 저하되므로, 개발자가 직접 확인하는 수동 체크리스트로 관리합니다.

## 3. 매니페스트 인식 확인

**판단 근거:** 매니페스트 파일(`src/.codex-plugin/plugin.json`)의 `skills` 필드가 유효하지 않은 경로를 가리키더라도 Codex CLI는 별도의 오류 메시지 없이 해당 스킬을 건너뜁니다. 따라서 플러그인 추가 명령이 성공하더라도 `plugin list`를 통해 활성화 상태를 직접 확인해야 합니다.

```bash
codex plugin marketplace add .
codex plugin add k-accounting@k-accounting-marketplace
codex plugin list
```

**판정 기준**: 마지막 명령 출력에 아래처럼 `installed, enabled` 상태가 보이면 통과다.

```
k-accounting@k-accounting-marketplace  installed, enabled  0.1.0  <저장소 경로>/src
```

이미 설치된 상태에서 반복 확인하려면 `codex plugin remove k-accounting@k-accounting-marketplace`로 지운 뒤 위 3줄을 다시 실행한다.

## 4. 스킬 트리거율 확인

**판단 근거:** 스킬 트리거는 단순 키워드 매칭이 아니라 언어 모델이 사용자 질의와 `SKILL.md`의 설명을 대조하여 판단하는 과정입니다. 따라서 대표적인 회계 질문을 입력하여 스킬이 의도대로 활성화되는지 반복 검증합니다.

새로운 Codex 세션에서 대표적인 회계 질의(예: "K-GAAP에서 현금흐름표의 영업활동현금흐름을 간접법으로 구할 때 대손상각비는 어떻게 가감하나요?")를 입력합니다. 세션 화면에 `k-accounting` 스킬 적용 표시가 나타나거나 답변에 조항 인용이 정상적으로 첨부되는지 확인합니다.

**판정 기준**: 질의 입력 시 스킬이 안정적으로 트리거되면 통과입니다. 만약 트리거되지 않는 유형이 발생할 경우 `SKILL.md`의 `description` 필드에 해당 회계 용어를 보강합니다. 스킬 문서를 수정할 때는 `src/skills/`와 `.claude/skills/`를 함께 갱신하고 `uv run pytest tests/unit/test_claude_skill.py`로 동기화를 검증합니다.

## 5. MCP 도구 실제 호출 확인

**판단 근거:** 플러그인에 번들된 MCP 서버는 전역 설정 목록에 노출되지 않을 수 있으므로, 실제 세션에서 도구를 호출하여 응답을 확인해야 합니다.

Codex 세션에서 `k-accounting` 스킬이 적용된 상태로 기준서 질의를 실행한 뒤, 최종 답변에 실제 조항 인용이 포함되는지 확인합니다.

**판정 기준**: 답변에 조항 인용이 하나 이상 정상적으로 포함되면 통과입니다. 도구를 찾을 수 없다는 오류가 발생하면 ① 저장소 루트 디렉터리에서 세션을 열었는지 확인하고, ② 매니페스트(`src/.mcp.json`)에 정의된 실행 커맨드가 정상 동작하는지 점검합니다.
