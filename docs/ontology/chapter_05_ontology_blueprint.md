# 제5장 회계정책, 회계추정의 변경 및 오류 온톨로지 설계안

대상 원문: `data/llm_parsed/제5장_회계정책,_회계추정의_변경_및_오류.md`

공통 노드, 공통 엣지, 필수 속성, part taxonomy, `extraction_status`, 실패 조건 중심 품질 기준은 `docs/ontology/common_schema.md`를 따른다. 이 문서는 제5장 특화 Rule과 추출 패턴만 정의한다.

이 문서는 제5장을 기준으로 온톨로지를 만들 때의 장별 추출 기준이다. 제5장은 회계정책 선택, 회계정책 변경, 회계추정 변경, 오류수정의 처리 순서가 핵심이다. 같은 "변경"이라는 단어가 반복되므로 정책 변경과 추정 변경을 반드시 구분해야 한다.

## 1. 핵심 방향

제5장은 다음 질문에 답할 수 있어야 한다.

- 회계정책은 어떤 순서와 근거에 따라 선택하는가?
- 회계정책 변경은 언제 허용되는가?
- 회계정책 변경은 소급 적용하는가, 전진 적용하는가?
- 회계추정 변경은 어떻게 회계처리하는가?
- 회계정책 변경과 회계추정 변경을 구분하기 어려울 때 어떻게 판단하는가?
- 전기오류와 중대한 전기오류는 어떻게 수정하는가?
- 각 변경과 오류수정에 대해 무엇을 공시해야 하는가?

제5장은 `PolicySelectionRule`, `PolicyChangeRule`, `EstimateChangeRule`, `ErrorCorrectionRule`, `DisclosureRule`을 중심으로 구성한다.

## 5. 주요 추출 패턴

### 5.1 회계정책 선택

5.3~5.6은 회계정책 선택의 우선순위로 모델링한다.

- `APPLIES_TO`: 회계정책 선택 규칙 -> 회계정책
- `REFERENCES`: 회계정책 선택 규칙 -> 관련 일반기업회계기준
- `HAS_CONDITION`: 구체적 기준이 없는 거래, 사건, 상황
- `REFERENCES`: 정책 개발 규칙 -> 재무제표 목적적합성, 신뢰성

5.5의 참조 순서는 `PolicyHierarchyRule`로 만들고 순서 속성을 둔다. 단순 `REFERENCES`만 남기면 우선순위 질의에 답할 수 없다.

### 5.2 회계정책 변경

5.9~5.13은 회계정책 변경 규칙으로 만든다.

- `HAS_CONDITION`: 기준 변경으로 요구되는 경우
- `HAS_CONDITION`: 더 신뢰성 있고 목적적합한 정보 제공
- `MEASURED_BY` 또는 `APPLIES_METHOD`: 소급 적용
- `HAS_EXCEPTION`: 다른 장이 특정 전환규정을 두는 경우
- `HAS_EXCEPTION`: 실무적으로 소급 적용이 불가능한 경우

5.10처럼 다른 장의 재평가모형 등이 우선되는 문장은 `REFERENCES`와 `HAS_EXCEPTION`을 함께 둔다.

### 5.3 회계추정 변경

5.14~5.17은 `EstimateChangeRule`로 만든다.

- `APPLIES_METHOD`: 전진 적용
- `RECOGNIZES_IN`: 당기손익 또는 관련 자산·부채 장부금액
- `HAS_CONDITION`: 추정의 변경, 새로운 정보, 새로운 상황

정책 변경과 추정 변경을 구분하기 어려운 경우는 `EstimateChangeRule`로 처리하는 판단 규칙을 별도로 만든다.

### 5.4 정책 변경과 추정 변경이 함께 있는 경우

5.15~5.16은 처리 순서가 중요하다.

- 먼저 회계정책 변경 효과를 누적적으로 반영한다.
- 이후 회계추정 변경 효과를 전진 적용한다.
- 구분할 수 없는 경우 회계추정 변경으로 본다.

이 부분은 `ProcessingOrderRule` 또는 `EstimateChangeRule`의 `sequence` 속성으로 표현한다.

### 5.5 오류수정

5.18~5.20은 전기오류와 중대한 전기오류를 구분한다.

- `CLASSIFIES_AS`: 오류 -> 전기오류, 중대한 전기오류
- `RECOGNIZES_IN`: 중요하지 않은 전기오류 -> 당기손익
- `APPLIES_METHOD`: 중대한 전기오류 -> 소급재작성 또는 기초잔액 조정
- `HAS_CONDITION`: 비교재무제표 표시 여부, 실무상 적용 가능 여부

### 5.6 공시

5.21~5.24는 변경 유형별 `DisclosureRule`로 분리한다.

- 회계정책 변경: 변경 성격, 이유, 적용 금액, 소급 적용 효과
- 회계추정 변경: 변경 성격과 당기 및 미래기간 영향
- 오류수정: 오류 성격, 수정 금액, 비교재무제표 재작성 영향

## 6. 보충 자료 연결

- `결5.*`: 정책/추정/오류 처리 방식의 근거로 `BASIS_FOR` 연결
- `실5.*`: 변경 유형 판단, 소급/전진 적용 판단에 `SUPPLEMENTS` 연결

## 7. 품질 점검 기준

- 회계정책 변경과 회계추정 변경을 같은 `AccountingChange` 하나로만 만들지 않아야 한다.
- 소급 적용, 전진 적용, 소급재작성은 각각 별도 처리 방식 개념으로 둔다.
- `실무적으로 적용할 수 없는 경우`는 단순 텍스트가 아니라 예외 조건으로 표현한다.
- 전기오류와 중대한 전기오류는 수정 방식이 다르므로 별도 규칙으로 분리한다.
- 공시 조항은 변경 유형별로 독립 `DisclosureRule`로 만든다.

## 8. 산출물 초점

제5장 산출물은 변경 또는 오류 상황이 들어왔을 때 처리 방법을 결정할 수 있어야 한다. 즉 `무엇이 변경되었는가 -> 어떤 유형인가 -> 어떤 적용 방식인가 -> 어떤 공시가 필요한가`의 판단 흐름이 Rule과 관계로 남아야 한다.
